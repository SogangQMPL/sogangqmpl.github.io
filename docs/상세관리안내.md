# 연구실 홈페이지 상세 관리 안내

처음에는 [간편 관리 안내](https://sogangqmpl.github.io/admin/guide.html)의 순서대로 진행하세요. 이 문서는 항목별 기능과 기술 설정을 확인할 때 사용합니다. GitHub는 연구실 공용 계정 **SogangQMPL**을 사용합니다.

연구실 소개, 연구 분야, 구성원, 논문, 소식은 `content/site.json` 한 파일에 모여 있습니다. 디자인 코드를 수정할 필요 없이 한국어 편집 화면에서 입력할 수 있습니다.

## 홈 상단 공지 바꾸기

**기본 정보 → 홈 상단 공지**에서 제목·내용·링크를 입력합니다. **홈 상단 공지 표시**를 끄면 공지가 숨겨집니다. 모집 공고 외에도 일정이나 방문 안내를 넣을 수 있습니다. 링크는 `join.html` 같은 사이트 내부 페이지 또는 `https://` 주소를 사용하며, 필요 없으면 비워 둡니다.

홈에는 **큰 랩 이름과 대표 그림 → 상단 공지 → News → Publications** 순서로 표시됩니다. News와 Publications는 각각 3개씩 표시합니다. **기본 정보 → 홈 첫 화면**에서 랩 이름을 세 줄로 입력하고 대표 그림과 그림 설명을 바꿀 수 있습니다. PC에서는 이름 왼쪽·그림 오른쪽, 모바일에서는 이름·그림을 세로로 표시합니다. 랩 이름은 Wix와 같은 Quicksand 이탤릭이며 공지 제목은 PC 33px·모바일 26px입니다. **모집 안내**는 Join Us 페이지의 모집 정보를 관리합니다.

## 연구 주제·하위 주제·논문 연결

1. **연구 분야**에서 대주제를 엽니다. 대주제 제목·소개·아이콘과 **분야 개념도 (Research map)**를 수정할 수 있습니다. 상단 목차에는 분야와 하위 주제의 번호·제목만 표시하고, 연구 항목은 각 하위 주제의 **연구 초점**에서 관리합니다. 분야 개념도는 페이지 하단 Research map 안에 표시합니다.
2. 각 대주제의 **하위 주제**를 열어 제목·연구 초점·기본 schematic·짧은 소개·연구 상태를 수정합니다. **연구 초점**은 설명 위에 보이는 항목 목록이며 쉼표로 구분해 입력합니다. **기본 schematic**은 항상 보이는 도식입니다. **상세 설명**에서는 소제목별 본문과 관련 그림을 함께 관리합니다. **하위 주제 추가**, **위로·아래로**, **하위 주제 삭제**로 목록을 관리합니다. 삭제한 항목은 상단 **되돌리기**로 복구할 수 있습니다.
3. **논문 ID 확인**을 펼치면 논문 제목과 `pub-02` 같은 ID가 함께 보입니다. 각 하위 주제의 **관련 논문 ID**에 `pub-02, pub-03`처럼 입력하면 그 주제의 Related papers에 표시됩니다. 실제 논문 제목·저자·DOI는 **논문** 항목에서 한 번만 관리합니다.
4. 아직 관련 게재 논문이 없는 주제는 논문 ID를 비워 두고 연구 상태를 `Research direction`으로 둡니다. 관련 논문이 있는 주제는 `Published research`를 사용합니다. 기존에 연결된 논문이나 원문 출처는 확인 없이 바꾸지 마세요.
5. 존재하지 않는 논문 ID, 비어 있는 하위 주제명, 중복된 주제 ID는 저장·미리보기 전에 확인하도록 안내합니다. ID 자체는 편집기에서 자동으로 만들어집니다.

새 논문을 먼저 **논문**에 추가한 다음 연구 주제와 연결하세요. 하위 주제와 그 밖의 데이터는 전체 `site.json`에 함께 저장되므로, 일부 목록만 담은 JSON으로 교체하지 않습니다. 예전 파일에 공지나 하위 주제가 없어도 불러올 수 있지만, 현재 내용을 기준으로 수정하는 것을 권장합니다.

Research의 하위 주제에는 **기본 schematic**, **연구 초점**, **짧은 소개**와 **Related papers**를 바로 표시합니다. 관련 논문은 제목 아래에 학술지·권·페이지 또는 논문 번호·연도를 함께 표시하며, 논문 목록에서 수정하면 자동 반영됩니다. 관련 논문은 최신 연도순으로 표시합니다. **Research details +**를 누르면 소제목별 설명과 원본 그림이 펼쳐지고 **−**로 바뀝니다. 다시 누르면 접힙니다. 모든 도식은 일반 문서 흐름에 배치해 스크롤을 따라 움직이지 않습니다. 그림을 누르면 연결된 원본을 큰 화면으로 볼 수 있습니다.

**상세 설명 추가**로 설명 묶음을 만들고 **설명 제목**과 **설명 본문**을 입력합니다. 제목을 비우면 도입 문단으로 표시하며, 빈 줄로 본문 문단을 나눕니다. 각 설명 안의 **상세 그림 추가**에서 해당 내용의 그림·원본 주소·설명·캡션·출처를 관리합니다. 설명과 그림은 각각 순서를 바꾸거나 삭제할 수 있습니다. 원본 주소가 있으면 방문자가 그림을 눌러 큰 이미지로 볼 수 있습니다. 왼쪽 대표 그림은 다시 넣지 않아도 됩니다. 이전 형식의 초안을 불러오면 기존의 상세 설명·그림 입력 방식도 사용할 수 있습니다.

## 심사 중 논문 관리

**심사 중 논문**에서 제목·저자·연구실 저자·선택 링크를 입력하면 Publications 검색창 위의 **Under review**에 표시됩니다. 공개 논문 목록과 분리되어 있어 출판 연도·학술지·DOI를 임의로 입력할 필요가 없습니다. 저자 이름은 원고의 표기를 유지하고, 굵게·밑줄을 적용할 이름은 **연구실 저자**에 같은 철자로 입력합니다. 현재 원고의 Dianne Lee는 구성원 Jihyun Lee와 같은 인물로 확인되어 강조합니다.

게재가 확정되면 **논문**에 확정된 학술지·연도·링크와 함께 추가하고, **심사 중 논문**의 해당 항목을 삭제합니다. Under review 항목은 검색·연도 필터 아래의 게재 논문 수에 포함되지 않습니다.

## 평소에 소식이나 논문을 추가할 때

Publications는 **2010–2017년만 한 묶음**으로 표시하고, 나머지는 실제 논문 데이터에 있는 연도만 최신순으로 보여 줍니다. 특정 연도 목록을 미리 정해 두지 않으므로 새 연도의 논문을 추가하면 자동으로 새 묶음이 생깁니다. 논문의 **출판 연도**는 실제 연도를 입력하며, 묶는 범위는 `publicationYearGroups`에 별도로 보관합니다. 검색과 연도 필터도 같은 구분을 사용합니다.

논문 항목의 **논문 대표 그림**, **그림 설명**, **그림 이름**, **그림 출처 페이지**에서 Publications 왼쪽 그림을 관리합니다. 해당 논문의 graphical abstract나 연구 구조 그림을 사용하고, 원래 비율을 유지합니다. 그림 파일은 `assets/publications/`에 넣고 경로를 입력하세요. 방문자는 그림을 눌러 확대하고 출처 페이지로 이동할 수 있습니다. 그림은 Publications 목록에 표시하며 홈의 간결한 대표 논문 목록에는 표시하지 않습니다.

목록의 그림 아래에는 Figure 1·Graphical abstract 같은 표기를 넣지 않습니다. 그림 이름과 출처는 확대창에서 확인할 수 있습니다. 여러 패널로 된 그림은 목록에서 대표 장치·시료·도식을 미리 보여 주며, 확대하면 원그림 전체가 표시됩니다. 편집기에서 그림 주소를 바꾸면 이전 패널 미리보기 범위는 자동으로 해제됩니다.

논문 저자 목록에서 교수님과 연구실 구성원은 `Seongwon Gim, Hyeonjun Baek`처럼 풀네임으로 작성합니다. **연구실 저자 (굵게·밑줄)**에도 저자 목록과 같은 풀네임을 입력합니다. 지정한 이름에 굵게·밑줄을 적용하며, 저자 순서와 공동 기여 표시 `*`는 유지합니다. 연구실 저자 항목에 입력할 때 `*`는 제외하세요. 이니셜이 같아도 외부 연구자일 수 있으므로 논문별로 신원을 확인하고, 다른 연구자의 이름을 임의로 확장하지 않습니다.

1. 홈페이지 주소 뒤에 `/admin/`을 붙여 편집 화면을 엽니다. 예: `https://소유자.github.io/저장소/admin/`.
2. **소식**, **논문**, **구성원**, **연구 분야** 중 편집할 항목을 선택합니다. 기존 항목의 제목을 누르면 입력창이 펼쳐집니다. **새 항목 추가**로 새 항목을 만듭니다.
3. 제목과 내용을 입력합니다. 논문의 **홈 화면의 대표 논문에 표시**를 선택하면 대표 논문 영역에도 사용됩니다. 기존 자료의 DOI와 출판 연도는 원문을 확인해 입력해 주세요.
4. **브라우저에 초안 저장**을 누릅니다. 저장한 초안은 같은 브라우저와 같은 사이트 주소에서 다시 불러올 수 있습니다. 다른 컴퓨터나 브라우저로 옮겨지지 않습니다. 브라우저 저장 공간을 지우면 사라집니다.
5. **미리보기**를 눌러 새 창에서 확인합니다. 미리보기 주소에는 `?preview=1`이 붙습니다. 공개 사이트의 실제 내용은 바뀌지 않습니다.
6. **site.json 다운로드**를 누릅니다. 다운로드 폴더에서 파일 이름이 `site (1).json`처럼 바뀌었다면 업로드 전에 `site.json`으로 이름을 맞춥니다.
7. GitHub 저장소의 **content** 폴더를 엽니다. **Add file → Upload files**에서 방금 받은 **site.json**을 올립니다. 파일 경로가 **content/site.json**인지 확인합니다. 저장소 맨 위에 올리면 홈페이지에 반영되지 않습니다.
8. **Commit changes**를 눌러 저장합니다. 직접 저장할 권한이 없다면 GitHub에 로그인하거나 저장소 관리자에게 편집 권한을 요청해야 합니다. 조직에서 검토를 요구한다면 제안한 변경을 관리자가 승인해야 합니다.
9. 저장소의 **Actions**에서 Pages 게시 작업이 성공했는지 확인하고, 홈페이지의 일반 주소를 새로고침합니다. 게시에는 잠시 시간이 걸릴 수 있습니다. 이전 화면이 보이면 새로고침하고, 주소에 `?preview=1`이 남아 있지 않은지도 확인합니다.

**초안 저장·미리보기·파일 다운로드는 게시가 아닙니다.** 공개 사이트는 GitHub에 파일을 반영하고 배포가 완료되어야 바뀝니다. 편집 화면에 접속할 수 있다는 사실만으로 저장소의 수정 권한이 생기지 않습니다. 편집 화면에는 비밀번호나 GitHub 토큰을 입력할 필요가 없습니다.

## 기존 글 수정, 삭제, 순서 변경

- 항목 제목을 누른 뒤 값을 고칩니다. 제목과 이름이 같은 항목이 있으면 날짜·연도를 함께 확인하세요.
- **항목 삭제**는 현재 초안에서만 삭제합니다. 실수했다면 상단 **되돌리기**로 복구합니다. 최근 25번의 수정을 되돌릴 수 있으며 페이지를 다시 열면 되돌리기 기록은 사라집니다.
- **위로·아래로**로 목록 순서를 바꿉니다. 공개 화면에서 날짜·연도로 정렬하는 목록은 그 정렬 규칙이 우선합니다.
- 저장 초안을 지우더라도 현재 편집 화면이나 공개 사이트가 삭제되지는 않습니다.
- 원래 공개 내용을 다시 시작점으로 삼으려면 편집 화면을 새로고침하고 **초안 불러오기**를 누르지 마세요.

## News·Activities 게시물과 사진 편집

**소식 · Activities**에서 게시물을 열면 제목·날짜·분류와 **게시물 내용**을 수정할 수 있습니다. 분류가 `Activities`이면 활동 목록에, 다른 분류이면 News에 표시됩니다. 방문자는 Wix로 이동하지 않고 이 홈페이지 안에서 글과 사진을 봅니다. **Wix 원문 · 출처 주소**는 이관한 원문을 기록하는 항목입니다.

`Conferences`는 **행사당 게시물 하나**로 작성합니다. 발표자와 추가 참석자를 구분하고 같은 행사의 사진·발표 제목은 한 글에 모읍니다. 개인 수상 소식은 `Awards`에 별도 게시합니다. 제목 뒤의 이름은 `Awards`에만 붙입니다. `Conferences` 제목은 행사명 뒤에 확인된 발표 형식(Poster Presentation, Oral Presentation, 둘 다 있으면 Oral & Poster Presentations)을 붙입니다. 개인 이름은 제목에 붙이지 않고 발표자·참석자 이름과 전원 참석 여부는 본문에 적습니다. 통합된 기존 주소는 `aliases`에 보관하여 행사 글로 자동 연결합니다.

News와 Activities 목록에는 **큰 대표 사진·제목·날짜**를 표시합니다. Awards는 **수상 소식 핵심 정보**에서 수상자·상명·행사를 입력하면 목록에 구분해서 표시합니다. 핵심 정보가 없거나 다른 분류이면 **목록 소개 (선택)** 또는 게시물 본문 앞부분을 최대 두 문단 사용하며, 본문이 없는 게시물에는 문구를 추가하지 않습니다. 사진이나 글을 누르면 개별 게시물에서 전체 내용을 볼 수 있습니다. 대표 사진을 비워 두면 본문 첫 사진을 사용합니다.

1. **게시물 내용**에서 문단·소제목·사진·목록·인용 중 하나를 선택하고 **내용 추가**를 누릅니다. 각 블록의 **위로·아래로**로 글과 사진의 순서를 정합니다.
2. 사진 블록에는 `assets/posts/workshop-2026.jpg` 같은 **사진 파일 주소**, **사진 설명**, 필요하면 **사진 아래 설명**을 입력합니다. 고해상도 파일을 따로 보관한다면 **원본 사진 주소 (선택)**에 그 경로를 입력합니다. 이 항목을 비워 두면 표시용 사진으로 원본을 봅니다. 실제 파일은 아래 사진 업로드 방법에 따라 GitHub의 해당 경로에 올립니다. 편집 화면에서는 사진을 미리 확인할 수 있습니다.
3. **목록 소개 (선택)**로 목록에 보일 짧은 글을 따로 입력할 수 있습니다. 비워 두면 현재 본문의 앞부분을 자동으로 표시합니다. **이전 본문 (보관)**은 본문 블록이 없는 예전 게시물에서 사용하는 내용입니다. **목록 대표 사진**은 목록에 사용할 사진이며 본문 사진은 각각의 사진 블록에서 관리합니다.
4. **게시물 미리보기**를 누르면 해당 글을 초안으로 확인할 수 있습니다. 새 게시물도 미리 볼 수 있으며, 이때 공개 데이터는 바뀌지 않습니다.
5. 내용을 확인하고 전체 `site.json`을 다운로드해 저장소의 `content/site.json`에 반영합니다. 글마다 별도 HTML 파일을 작성할 필요는 없습니다. 배포 시 각 게시물 페이지가 자동 생성됩니다.

가져온 문단의 강조·문장 안 링크는 해당 문단을 수정하지 않으면 그대로 보존됩니다. 그 문단이나 목록을 직접 수정하면 일반 글자로 바뀝니다. **내용 삭제**를 잘못 눌렀다면 상단 **되돌리기**로 복구하세요. 기존 글에 사진이 여러 장 있을 때 대표 사진 하나로 본문 사진 목록을 대체하지 마세요.

## 사진·연구 그림 교체

1. 공개해도 되는 JPG, PNG, WebP 또는 SVG 파일을 준비합니다. 사진은 가급적 가로 1600px 이내로 줄여 파일을 가볍게 만듭니다.
2. 파일명은 `baek-profile.jpg`, `moire-device.webp`처럼 짧게 짓습니다. 기존 이름을 재사용하면 해당 사진이 사용된 곳도 함께 바뀔 수 있습니다.
3. GitHub 저장소의 **assets** 폴더에서 **Add file → Upload files**로 올리고 **Commit changes**를 누릅니다.
4. 편집 화면의 사진 또는 연구 그림 주소에 `assets/baek-profile.jpg`처럼 입력합니다. `C:\Users\...` 같은 컴퓨터 파일 경로를 입력하면 방문자에게 사진이 보이지 않습니다.
5. 연구 그림에는 **그림 설명**도 입력합니다. 예: “두 층의 반도체를 겹친 모아레 구조의 개념도.”
6. 미리보기로 확인한 뒤 `site.json`을 다운로드하고 위의 게시 순서로 반영합니다.

구성원·연구 분야 등의 이미지에는 공개된 `https://` 주소도 쓸 수 있지만, News·Activities 본문 사진은 GitHub에 올린 `assets/posts/파일명`을 사용합니다. 이미지 주소를 입력하는 것 자체가 파일 업로드는 아닙니다.

## 초기 GitHub Pages 설정

아직 저장소가 없다면 기본 브랜치를 `main`으로 한 새 저장소를 만들고 이 사이트 폴더의 **내용 전체**를 저장소 최상위에 올립니다. 최상위에 `package.json`, `template.html`, `renderer.js`, `app.js`, `styles.css`, `content`, `assets`, `admin`, `scripts`, `.github`가 보여야 합니다. `qmp-lab` 폴더 자체 안에 한 단계 더 넣지 마세요. 숨김 폴더인 `.github`와 그 안의 `.github/workflows/pages.yml` 배포 설정도 포함해야 합니다. `dist`는 자동 생성되는 게시 결과이므로 올리지 않습니다.

저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다. **Actions → Publish lab website → Run workflow**를 실행하거나 `main`에 변경을 저장합니다. 작업이 콘텐츠를 검증하고 `node scripts/build.mjs`로 `dist` 폴더에 HTML과 자료를 만든 뒤 `dist`를 Pages에 게시합니다. Actions에서 성공 여부를 확인하면 게시 URL은 저장소의 Pages 설정에 표시됩니다. GitHub 계정·조직의 요금제와 정책에 따라 저장소 공개 여부와 Pages 이용 가능 범위가 달라질 수 있습니다. 기존 Wix 주소는 자동으로 변경되지 않으므로, 새 주소와 PC·모바일 화면을 검토한 후 전환합니다.

초기 로컬 검토는 Node.js 20 이상에서 `node scripts/check.mjs`, `node scripts/build.mjs`, `node scripts/serve.mjs` 순서로 실행합니다. 안내된 `http://127.0.0.1:4173/`과 `/admin/` 주소를 엽니다. 외부 패키지 설치는 필요 없습니다. 파일을 더블클릭한 `file://` 주소에서는 브라우저가 콘텐츠 파일 읽기를 차단할 수 있으므로 로컬 HTTP 서버를 사용합니다. 로컬에서 실제 콘텐츠를 바꿀 때는 다운로드한 파일로 **원본 `content/site.json`**을 교체한 다음 다시 빌드합니다. `dist/content/site.json`만 고치면 다음 빌드에 덮어써집니다.
