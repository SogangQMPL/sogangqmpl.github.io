# 연구실 홈페이지 분석과 개편 설계

검토일: 2026년 11월 1일 · 대상: H. Baek Research Group / Quantum Materials & Photonics Lab, Sogang University

이번 개편에는 **GitHub Pages용 정적 웹사이트와 한국어 콘텐츠 편집기**를 권장한다. Codex가 디자인과 기능을 코드로 관리하고, 다른 구성원은 정해진 입력칸으로 내용을 고칠 수 있도록 역할을 나누는 방식이다. Google Sites의 화면 편집이 배우기 더 쉽다는 장점은 인정하되, 이번 요청의 디자인 자유도·PC와 모바일의 일관성·Codex 관리 편의성을 함께 고려한 선택이다.

이 문서는 공개 사이트의 현재 내용과 브라우저 관찰을 바탕으로 한 분석이다. 기존 Wix의 모든 하위 페이지, 모든 기기, 실제 편집 권한을 가진 관리자 화면까지 검증한 것은 아니다. 참고 사이트의 색상·구성에 대한 평가는 디자인 판단이며, 플랫폼 기능에 대한 설명은 아래 공식 문서를 근거로 구분했다.

## 2. 현재 Wix에서 우선 해결할 문제

### 홈에서 연구실의 가치가 충분히 드러나지 않는다

[현재 홈](https://baahyyjuu.wixsite.com/hyeonjun)은 연구실명, 대표 이미지, 모집 문구가 중심이다. 첫 방문자가 연구 분야·대표 성과·최근 활동을 파악하려면 다른 페이지로 이동해야 한다. 연구 내용과 논문이 이미 있는 만큼 홈에 요약을 재사용하면 된다. 연구 소개를 먼저 이해한 뒤 논문 또는 지원 안내로 이동하도록 순서를 정리하는 것이 좋다.

### 시각 규칙이 여러 방향으로 나뉘어 있다

PC 브라우저에서 큰 이탤릭 연구실명, 가장자리가 흐려진 대표 이미지, 보라색 모집 문구, 남색 하단, Wix 배너와 채팅 오버레이를 관찰했다. 각각이 시선을 끌어 제목·연구 그림·핵심 정보의 우선순위가 약해진다. 본문과 메뉴의 기준선을 맞추고 글꼴·색상·간격을 공통 규칙으로 관리할 필요가 있다. 문의를 이메일로 운영한다면 채팅 기능을 계속 사용할지도 결정해야 한다.

### 메뉴와 본문에서 정보를 묶는 기준이 다르다

[Research](https://baahyyjuu.wixsite.com/hyeonjun/research)의 상단 메뉴에는 모아레, 층간 엑시톤, SPDC, 반도체 소자, 양자 광원이 있고, 본문은 Quantum information·Solid-State Physics·Semiconductor Devices로 구성되어 있다. 세부 현상과 큰 연구 분야의 수준이 섞여 있어 두 분류의 관계를 설명해야 한다.

[Member](https://baahyyjuu.wixsite.com/hyeonjun/member)는 PI 소개가 중심이고, 별도의 [Students](https://baahyyjuu.wixsite.com/hyeonjun/students) 페이지에는 학생 7명이 있다. 홈에서 확인되는 메뉴와 Students에서 확인되는 메뉴도 완전히 같지 않다. People 아래에서 PI·박사과정·석사과정·졸업생을 예측 가능하게 찾아가도록 정리하는 것이 좋다. Highlights·News·Activities는 News 안에서 논문·수상·Lab life 등으로 분류할 수 있다.

### 성과와 데이터의 정확성을 함께 다뤄야 한다

[Publication](https://baahyyjuu.wixsite.com/hyeonjun/publication)의 46개 항목을 새 사이트 데이터로 이전했다. 홈에도 대표 논문을 연결했다. 원본에서 확인한 아래 서지 문제는 새 데이터에서 수정했다.

- 2026년 chiral-phonon 논문의 `0, 00` 표기는 제거했다. 출판사 인용 정보에서 확인되는 저널·연도·DOI로 표시했다. [출판사 원문](https://www.nature.com/articles/s41699-026-00701-5)
- 2020년 nanotube Schottky diode 논문은 출판사 등록 Crossref 정보에 따라 **Nano Energy 76, 104955 (2020)**, DOI `10.1016/j.nanoen.2020.104955`로 고쳤다. [논문 DOI](https://doi.org/10.1016/j.nanoen.2020.104955)
- 2014년 GaN micro-rods 논문은 AIP 출판사 정보에 따라 **APL Materials 2, 092512 (2014)**, DOI `10.1063/1.4894780`으로 고쳤다. [논문 DOI](https://doi.org/10.1063/1.4894780)

이 세 항목의 발견된 문제는 해결했다. 모든 논문의 각 서지 필드를 출판사와 전수 대조했다는 의미는 아니다. 공개 페이지에서 확인한 PI 1명과 학생 7명은 사이트상의 인원이며, 현재 실제 재적 인원과 직급은 게시 전 연구실 확인 대상이다.

메뉴는 **Home · Research · People · Publications · News · Join Us**를 기준으로 한다. 홈은 각 정보의 요약과 다음 이동 경로를 제공하고, 전체 논문·전체 소식·상세 이력은 해당 페이지나 펼쳐보기에서 확인하도록 한다.

| Latest news | 최신 3~4건 | 날짜·종류·제목을 일관되게 표시하고 전체 기록으로 연결한다. |

연구 분류는 다음 세 축을 출발점으로 제안한다. 최종 학술 범위와 명칭은 PI가 확인해야 한다.

1. **Excitons & Moiré Physics**: 층간 엑시톤, 모아레 퍼텐셜, 전기장 제어, 상관 상태.
2. **Quantum & Nonlinear Photonics**: 양자 광원, 단일광자, SPDC, 비선형 광학.
3. **Semiconductor & Optoelectronic Devices**: 반도체 소자, 발광·검출, 뉴로모픽 응용.

흰색 또는 옅은 중성 배경과 짙은 본문색을 기본으로 하고 포인트 색상을 제한한다. 제목의 크기·굵기, 본문 길이, 구분선과 여백으로 위계를 만든다. 연구 그림은 장식과 실제 데이터의 역할을 구분하고 설명을 붙인다. 타 연구실의 논문·인명·사진을 우리 연구실 성과처럼 옮기지 않는다.

## 5. PC와 모바일 설계·검증 기준

다음 기준으로 PC와 모바일 화면을 구성했다. 아래 표는 설계 의도이며, 실제 확인을 마친 항목과 범위는 표 다음에 기록했다.

| 요소 | PC | 모바일 |
| --- | --- | --- |
| 첫 화면 | 소개와 연구 그림을 두 열로 구성 | 제목→설명→버튼→그림 순서로 읽기 |
| 메뉴 | 충분한 간격의 상단 메뉴 | 펼침 메뉴, 현재 상태 안내, 키보드와 터치 사용 |
| 연구·구성원 | 화면 폭에 따라 여러 열 | 한 열 또는 읽을 수 있는 간결한 배열 |
| 소식 | 날짜·분류·제목의 정렬 | 긴 제목이 잘리지 않도록 자연스럽게 줄바꿈 |
| 논문 | 연도별 목록과 검색·필터 | 저자·제목·DOI가 화면 폭을 넘지 않도록 줄바꿈 |
| 본문·버튼 | 적절한 최대 본문 폭 | 본문 약 16px 이상, 터치 영역 약 44px 이상을 시작 기준으로 사용 |
| 그림 | 불필요한 흐림 없이 선명하게 | 화면 폭에 맞추고 그림 속 작은 글씨에만 정보 전달을 의존하지 않기 |

로컬 브라우저에서 다음 항목을 확인했다.

| 확인 항목 | 확인 결과 |
| --- | --- |
| PC 1440px / 모바일 390px | Home·Research·People·Publications·News·Join Us 6개 페이지에서 가로 넘침 0, 깨진 이미지 0 |
| 좁은 모바일 320px | 6개 페이지 모두 가로 넘침 0 (`scrollWidth` 305px / `innerWidth` 320px) |

이는 로컬 브라우저에서 1440px·390px·320px 화면 폭으로 확인한 결과다. 실제 휴대전화·모든 브라우저·모든 키보드와 보조기술 조합의 검증 또는 공개 배포 후 검증을 뜻하지 않는다. 이메일·DOI 목적지의 전체 응답, 모든 이미지 대체 텍스트와 키보드 포커스 흐름도 위 결과만으로 전부 통과했다고 단정하지 않는다.

## 6. 관리 방식과 인수인계

내용은 하나의 데이터 원본에서 관리하고, 홈의 대표 논문·소식과 전체 목록이 같은 데이터를 사용하도록 한다. 논문 추가 때 홈과 Publications를 각각 수정하지 않게 하는 것이 핵심이다.

한국어 편집기의 운영 방식은 **내용 불러오기 → 입력칸 수정 → 파일 다운로드 → GitHub 저장소에 업로드 → Commit changes → 배포 결과 확인**이다. 편집기는 데이터 문법 실수를 줄이는 보조 도구다. 다운로드만으로 공개 홈페이지에 저장되는 자동 CMS가 아니며, 서버 계정·관리자 로그인·클라우드 자동 저장 기능을 제공하는 것으로 설명하면 안 된다. 브라우저에서 GitHub 파일을 직접 수정하는 방법도 대안이다. [GitHub 파일 편집 공식 안내](https://docs.github.com/en/repositories/working-with-files/managing-files/editing-files)

입력할 정보는 논문의 제목·저자·저널·연도·DOI·대표 여부, 소식의 날짜·제목·종류·본문, 구성원의 이름·역할·사진·소개, 연구 분야의 제목·요약 등으로 고정한다. 후임자는 한국어 안내를 따라 가장 흔한 업무인 소식 추가, 논문 추가, 구성원 변경을 연습하면 된다. 연구실이 소유한 저장소와 명확한 관리자 권한 구조를 사용하는 것이 인수인계에 유리하다.

## 7. 데이터 확인과 전환 우선순위

1. **게시 전 필수**: PI의 직급과 이력, 학생 7명의 현재 소속·과정, 연락처·호실을 연구실에서 확인한다. 논문 46개는 원본 목록에서 이전했고 위의 서지 문제 3건은 수정했다. 전체 서지 전수 대조는 별도 범위다. 오래된 논문은 현재 연구실 설립 후 성과와 PI의 전체 연구 이력을 혼동하지 않게 표기한다.
2. **시안 평가**: 홈 정보 우선순위, 연구 3개 축, 대표 논문 선정을 연구실에서 검토한다. PC 1440px·모바일 390px·320px의 6개 페이지와 핵심 기능 확인은 위 결과와 같다.
3. **운영 준비**: 연구실 GitHub 소유자·관리자, 저장소, Pages 배포 설정, 한국어 편집 절차를 정한다.
4. **전환**: 검토된 새 주소에서 확인한 뒤 기존 Wix의 링크·검색 노출·필요한 도메인 연결을 정리한다. 기존 사이트를 없애는 것은 별도의 전환 결정이다.

현재 작업은 GitHub Pages용 사이트의 로컬 구현·미리보기·위 범위의 기능 검증을 마친 상태다. **사용자는 아직 GitHub 저장소가 없다고 답했고, 새 원격 저장소 업로드와 실제 GitHub Pages 배포는 완료되지 않았다.** GitHub 연결은 제안된 상태이며 설치·연결 완료도 확인되지 않았다. 따라서 현재 결과를 공개 웹사이트 주소가 생긴 것으로 설명하면 안 된다. 이후 저장소 생성·업로드·Pages 설정·배포 확인이 필요하다. GitHub Pages 자체에는 서버 기반 CMS가 없으며, 일반 연구실 사이트 규모에 충분한 정적 호스팅이지만 사이트 크기 등 사용 제한은 적용된다. [GitHub Pages 제한](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)
