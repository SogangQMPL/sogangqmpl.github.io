설치·복제·인증 준비·수정·게시를 이어서 진행하는 요청문입니다. 새 PC의 최초 로그인·권한 승인·추가 인증 또는 설치 승인에는 담당자의 조작이 필요할 수 있습니다.
이 파일에는 비밀번호가 없습니다. 이전 비밀번호 포함 전달본 대신 이 요청문을 사용하세요.

[내 요청]
아래 절차에 따라 이 PC를 준비하고, 맨 아래에 적은 홈페이지 수정과 게시까지 완료해줘. 이미 있는 설치·인증은 재사용해줘.
Chrome의 ChatGPT 확장 프로그램, 브라우저 원격 제어, 파일 URL 접근 허용을 필수 조건으로 요구하지 마. 기존 문서에 브라우저 연결·웹 업로드를 먼저 요구하는 내용이 남아 있으면 이 요청문의 명령줄 절차를 우선해줘.

1. 실행 환경과 소스 준비
- 로컬 파일 수정·명령 실행이 가능한 Codex인지 확인해줘. 일반 ChatGPT 웹 대화처럼 그 기능이 없으면, 로컬 Codex에서 작업 폴더를 열어야 한다는 한 단계만 안내해줘.
- OS와 Git, Node.js 22 이상, GitHub CLI(gh)의 설치 여부·버전을 확인해줘. Codex에 포함된 도구도 정상 실행되면 재사용하고, 정상 도구를 불필요하게 재설치하거나 업그레이드하지 마.
- 없는 도구만 공식 배포처에서 설치해줘. Windows의 winget이 있으면 정확한 패키지 ID와 --source winget을 사용해줘: Git.Git, GitHub.cli, OpenJS.NodeJS.LTS. 설치 후 실제 Node.js 버전이 22 이상인지 확인해줘. winget이 없으면 공식 설치 경로를 사용하고, 관리자·조직 정책 승인이 필요할 때만 그 단계를 알려줘. 다른 OS에서는 해당 OS의 설치 방법을 사용해줘.
- 설치 후 현재 세션의 PATH가 갱신되지 않으면 실행 파일을 찾아 전체 경로로 실행하거나 현재 프로세스의 PATH만 보완해줘. 설치 성공과 실제 명령 실행을 각각 확인해줘.
- 현재 폴더의 Git 상태·브랜치·원격 주소를 확인해줘. 해당 저장소의 복제본이면 기존 작업을 보존하며 재사용하고, 없으면 현재 작업 공간의 새 하위 폴더에 위 HTTPS 저장소를 복제해줘. 관련 없는 파일을 덮어쓰지 마.
- AGENTS.md, README.md, 관리안내.md를 읽고 기존 프로젝트를 유지해줘. 이 사이트의 일반 검사·빌드에는 외부 npm 패키지 설치가 필요 없어.

2. Chrome 확장 프로그램 없이 GitHub 인증
- gh auth status --hostname github.com 으로 기존 인증을 확인해줘. 토큰 표시 옵션은 쓰지 마. GH_TOKEN·GITHUB_TOKEN 등이 있으면 값은 출력하지 말고, 그 인증이 실제 사용자 확인에 영향을 주는지 판단해줘. 다른 계정의 토큰이 정상 로그인을 막으면 사용자·시스템 환경변수는 보존하고 해당 명령 프로세스에서만 그 변수를 제외한 뒤 인증해줘. GH_HOST 같은 기존 호스트 설정도 실제 작업이 github.com을 향하는지 확인해줘.
- gh api --hostname github.com user --jq .login 으로 실제 사용자가 SogangQMPL인지 확인해줘. 이어서 gh api --hostname github.com repos/SogangQMPL/sogangqmpl.github.io --jq '{repository: .full_name, push: .permissions.push}' 로 저장소와 쓰기 권한을 확인해줘. 공개 조회·복제만으로 게시 권한을 판단하거나 권한 확인용 시험 커밋을 만들지 마.
- SogangQMPL 인증이 이미 있으면 재사용해줘. 다른 계정만 있으면 기존 계정을 삭제·로그아웃시키지 말고 등록된 SogangQMPL 인증으로 전환하거나 정상 로그인으로 추가해줘.
- 필요한 인증이 없으면 다음 명령을 실행해줘:
  gh auth login --hostname github.com --git-protocol https --web --clipboard
- 일회용 기기 코드와 일반 브라우저 인증 화면을 준비해줘. 명령이 Enter 입력을 기다리면 보내서 브라우저를 열어줘. 자동으로 안 열리면 명령이 안내한 GitHub URL과 코드를 알려줘. 로그인·기기 코드·권한 승인은 내가 그 브라우저에서 완료하도록 한 번 안내하고 실행 중인 인증 절차를 유지해줘. Chrome을 직접 제어할 확장 프로그램은 필요 없어.
- GitHub가 Google 로그인을 요구할 때만 정상 로그인 화면에서 위 공용 Google 계정을 선택하도록 안내해줘. Google 로그인과 GitHub CLI 인증은 별개야. 제어 연결이 없는 Chrome의 Google 로그인 상태를 확인했다고 주장하지 마.
- 터미널에서 'Authenticate Git with your GitHub credentials?'를 물으면 No로 답하고 GitHub CLI 로그인은 계속해줘. 다른 프로젝트를 건드리지 않도록 전역 Git 인증 설정 대신 아래의 명령별 도우미를 사용해줘.
- 인증이 끝나면 실제 사용자와 이 저장소의 쓰기 권한을 다시 확인해줘. 추가 인증·CAPTCHA·최초 계정 연결·새 권한 승인이 필요하면 그 화면만 안내하고, 보호를 우회하거나 새 계정을 만들지 마.
- OS 보안 저장소를 사용하는지 상태와 경고로 확인해줘. 보안 저장소 문제로 평문 파일에 저장됐다는 경고가 있으면 숨기거나 보안 저장 완료라고 하지 마. --insecure-storage, --show-token, gh auth token, 브라우저 쿠키·토큰 추출은 사용하지 마. 비밀번호·토큰·인증 캐시를 채팅·프로젝트·커밋·전달 파일·ZIP에 복사하지 마.
- 인증 대기 중에도 가능한 복제·수정·검사·빌드는 계속해줘. 미완료 인증을 완료로 보고하지 마.

3. 수정과 PC·모바일 확인
- 맨 아래에 수정 내용이 있으면 기존 디자인과 자료를 유지하면서 적용해줘. 구체적인 수정이 없으면 환경 준비·검사·미리보기까지 진행하고 바꿀 내용을 물어봐. 임의로 변경·게시하지 마.
- content/site.json, renderer.js, styles.css 등 원본을 수정해줘. dist는 생성 결과이므로 원본 대신 수정하지 마.
- node scripts/check.mjs 와 node scripts/build.mjs 를 실행하고 변경 범위에 맞는 기존 검사를 실행해줘.
- 화면 변경은 사용 가능한 내장 브라우저나 승인된 미리보기 도구로 PC·모바일을 확인해줘. Chrome 확장 프로그램이 없다는 이유로 인증·빌드를 중단하지 마. 시각 확인 도구가 없으면 로컬 미리보기 주소를 열어 내가 확인하도록 안내하고 직접 확인하지 않은 부분을 구분해줘.

4. Git 명령으로 게시
- 검증한 이 프로젝트의 기존 Git 인증이 정상적이면 재사용해도 돼. GitHub CLI 인증을 쓸 때는 gh가 현재 프로세스 PATH에 있는지 확인하고, 인증이 필요한 Git 명령에만 다음 설정을 적용해줘:
  git -C <실제저장소경로> -c 'credential.helper=' -c 'credential.https://github.com.helper=' -c 'credential.https://github.com.helper=!gh auth git-credential' <Git명령과인자>
- <...>는 실제 경로와 인자로 바꾸는 자리야. 명령 문자열을 임의로 조합하지 말고 셸에 맞게 경로·인자를 안전하게 전달해줘. 토큰을 직접 읽거나 URL에 붙이지 마. gh auth setup-git 으로 전역 설정을 무조건 바꾸지 마.
- 게시하지 말라는 요청이 없다면 수정·검증 후 변경한 원본·자료만 커밋하고 main에 반영해줘. 원격 변경을 먼저 확인하고 충돌을 보존하며 해결해줘. 강제 push나 다른 사람의 변경 삭제는 하지 마. 브랜치 보호가 있으면 정상 PR·승인 절차를 따라줘.
- 커밋 작성자 설정이 없으면 저장소 범위에서 올바른 작성자를 설정해줘. PC 전체의 작성자 정보를 임의로 바꾸지 마.
- gh run list --repo github.com/SogangQMPL/sogangqmpl.github.io --workflow pages.yml --branch main --commit <실제커밋SHA> 로 해당 커밋의 배포를 찾아 완료를 확인해줘. 현재 gh 버전에서 옵션이 지원되지 않으면 공식 도움말에 따라 같은 커밋의 실행을 조회해줘. 장시간 대기 중에는 상태를 알려줘.
- Publish lab website 성공과 실제 공개 페이지·자료 갱신까지 확인해야 게시 완료야. 로컬 빌드·커밋·push만으로 완료라고 하지 마.
- 별도 화면 편집기의 코드·스타일 변경도 필요하면 기존 qmp-editor-host 소스와 Sites 호스팅 권한을 확인해줘. GitHub 권한만으로 편집기 서버를 배포할 수 있다고 가정하지 마. 권한이 없으면 홈페이지 작업을 완료하고 편집기 미반영 범위를 알려줘.
- 마지막에는 실제 GitHub 계정·수정 권한, 검사·PC/모바일 확인 범위, 게시 결과와 공개 링크를 짧게 알려줘. 내가 직접 완료해야 할 인증·설치 단계가 남으면 정확히 한 단계씩 알려줘.
