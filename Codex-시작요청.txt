[내 요청]
PC마다 설치와 로그인 상태가 다르니 아래 확인부터 시작해서, 이번에 요청한 홈페이지 수정과 게시까지 이어서 진행해줘. 이미 완료된 설정은 재사용하고 불필요한 설정이나 재로그인은 하지 마.

1. 작업 폴더와 환경
- 현재 폴더의 Git 상태, 브랜치와 원격 주소를 확인해줘. 이 홈페이지 복제본이 있으면 재사용하고, 관련 없는 폴더나 수정 중인 파일을 덮어쓰지 마. 복제본이 없으면 현재 작업 공간의 새 하위 폴더에 이 저장소를 복제해줘.
- Git과 Node.js 22 이상을 확인하고, 필요한 공식 설치를 허용된 범위에서 준비해줘. 설치 승인이 필요하면 그 단계만 정확히 알려줘.
- 저장소의 AGENTS.md, README.md, 관리안내.md를 읽고 현재 소스를 기준으로 작업해줘.

2. 사용할 브라우저 연결
- 이 PC의 기존 Chrome 등 사용자가 쓰는 브라우저에 Codex의 승인된 제어 연결이 있는지 확인해줘. 실제 작업할 브라우저 프로필을 기준으로 로그인 상태를 확인해줘.
- 연결이 없으면 필요한 연결 화면과 단계만 안내하고, 가능한 저장소 복제·검사·빌드는 계속 진행해줘. 아직 확인하지 못한 로그인이나 게시 권한은 완료됐다고 보고하지 마.
- 웹 파일 업로드에 파일 URL 접근 허용이 필요하면 확장 프로그램 설정의 해당 항목만 안내해줘. 로그인 상태와 파일 업로드를 지원하지 않는 브라우저를 임의로 대체해 완료됐다고 하지 마.

3. 공용 Google 로그인 확인 및 진행
- 먼저 Google 계정 화면 또는 계정 선택 목록에서 [공용 Google 계정 이메일]이 실제로 로그인되어 있는지 확인해줘. Chrome 프로필 이름, 기본 Google 계정 또는 비슷한 이메일만 보고 판단하지 마.
- 해당 계정이 있으면 재사용해줘. 다른 계정만 로그인되어 있으면 다른 계정을 로그아웃시키지 말고 공용 계정을 추가하는 정상 로그인 화면을 열어줘.
- 해당 계정이 없으면 accounts.google.com의 정상 로그인 절차로 진행해줘. 이 비공개 요청문에 비밀번호가 제공된 경우 그 로그인 화면에서만 사용해도 돼. 제공되지 않았다면 내가 로그인 화면에 직접 입력하도록 안내해줘.
- 추가 인증·CAPTCHA·보안 확인 또는 새 권한 승인이 요구되면 필요한 화면과 단계만 알려줘. 인증 보호를 끄거나 우회하지 마. 로그인 성공 후 계정 이메일을 다시 확인해줘.
- 비밀번호를 응답·로그·소스 파일·Git 커밋·백업 ZIP에 복사하지 말고, 브라우저 쿠키나 토큰을 추출하지 마. 비밀번호 저장 또는 계정 보안 설정을 임의로 변경하지 마.

4. GitHub 게시 경로 확인
- GitHub가 이미 SogangQMPL로 로그인되어 있으면 그 세션을 재사용해줘. 미로그인 상태면 GitHub 일반 로그인 화면의 Continue with Google에서 위 공용 계정으로 진행해줘.
- 로그인 결과가 SogangQMPL인지, 이 저장소를 수정할 권한이 있는지 확인해줘. 공개 저장소 조회나 복제 성공만으로 쓰기 권한이 있다고 판단하지 마. 권한 점검을 위한 시험 커밋은 만들지 마.
- 최초 계정 연결이나 신규 가입 화면이 나오면 내게 필요한 단계만 알려줘. 새 GitHub 계정을 만들거나 기존 계정 권한을 임의로 바꾸지 마.
- 기존 Git 인증이 정상적으로 있으면 재사용해도 돼. 없으면 승인된 브라우저의 GitHub 웹 업로드·커밋·PR 화면을 이용해 게시해줘. 이 경로를 사용했다고 Git 명령줄 인증까지 설정됐다고 보고하지 마.

5. 수정과 확인
- 아래에 이번 수정 내용이 있으면 기존 디자인과 나머지 자료를 유지하면서 바로 적용해줘. 수정 요청이 비어 있으면 위 준비와 미리보기까지 완료한 뒤 내가 바꿀 내용을 물어봐. 임의로 공개 사이트를 바꾸지 마.
- node scripts/check.mjs와 node scripts/build.mjs를 실행하고, 영향을 받는 PC·모바일 화면을 확인해줘. dist는 생성 결과이므로 원본 소스를 수정해줘.
- 로그인이나 브라우저 준비가 아직 완료되지 않아도 가능한 로컬 작업은 진행하고, 미확인 부분을 분명히 구분해줘.

6. 게시와 완료
- 사용자가 게시하지 말라고 하지 않았다면, 요청한 수정과 확인이 끝난 뒤 GitHub 반영과 공개 홈페이지 게시까지 완료해줘. 브라우저로 업로드할 때는 파일 경로와 변경 전체가 로컬 검증본과 일치하는지 확인해줘.
- main에 반영한 뒤 Actions의 Publish lab website가 성공했는지, 실제 공개 페이지가 바뀌었는지 확인해줘. 웹 커밋 후 로컬 저장소도 변경을 잃지 않도록 동기화해줘.
- 별도 화면 편집기의 코드·스타일에도 영향을 주면 기존 호스팅 권한과 소스가 있는지 확인해 동기화해줘. 해당 접근 권한이 없으면 홈페이지 게시 결과와 편집기 미반영 범위를 구분해서 알려줘.
- 마지막에는 Google 계정 확인, GitHub 계정·수정 권한, PC·모바일 검증, 공개 게시 결과와 링크를 짧게 알려줘. 준비만 됐거나 인증·게시가 미완료면 그 상태를 그대로 알려줘.
